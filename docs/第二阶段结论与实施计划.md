# 第二阶段结论与实施计划

日期：2026-11-14  
状态：**研究完成，等待确认；本阶段未修改任何项目代码、未构建 APK。**

---

## 1. 结论

1. **可行**：不依赖自建服务器、不依赖第三方在线 API，在 Android 本机解析抖音公开视频，已在本机 PC 级验证（`ttwid` 双请求 → `play_addr` → 206 `video/mp4`）。
2. **图集可行但未验证**：QingZai 与 DouyinKit 源码都实现了图集读取，本项目缺少有效图集链接，未做网络实测；阶段 4 必须补测后才能对外宣称。
3. **推荐路线**：原生 HTTP 快速通道（QingZai 思路，独立实现）+ WebView 钩子兜底（DouyinKit 思路，独立实现），落在现有 Kotlin 桥内；Python 只做适配与下载。
4. **不整体移植**：DouyinKit 约 2,900 行解析相关代码、douyin-material-saver 约 5,800 行且 GPL；整体移植成本高、风险大。只实现所需的解析、归一化、错误码与钩子。
5. **架构不变**：Kotlin + Chaquopy + Python 本地服务保留；现有 WebView UI、下载器、转换器不改接口。
6. **F1/F2/F5/F7/F8 均有对应方案**（见《推荐技术架构.md》§7）。
7. **许可证**：QingZai、DouyinKit 为 MIT，可参考/有限复用；douyin-material-saver 为 GPL-3.0，只读思路、不复制代码。

---

## 2. 最终选型

| 层 | 选型 | 理由 |
|---|---|---|
| 链接识别/短链 | Kotlin 自写 `LinkExtractor` + `ShortLinkResolver` | 需要区分过期短链、站外跳转；纯本地 |
| 快速通道 | Kotlin OkHttp/HttpURLConnection + 持久 Cookie | 已验证；2–6s；不需要 WebView |
| 兜底通道 | 透明 `ParseActivity` + 单 WebView + `hook.js`/`page_model.js` | 接口被过滤/图集/验证场景；MIT 思路 |
| 数据归一化 | Kotlin `DouyinDetailNormalizer`（自写，覆盖必要字段） | 视频多码率、图集、LivePhoto、BGM |
| 错误模型 | `error_code` 枚举 + 中文 message | 前端可区分动作 |
| Python 适配 | `engines._android_bridge_resolve` 改为多 item | 不改变下载/转换接口 |
| 第三方 API | 保留代码，默认关闭，仅显式模式 | 不违反“本地”约束；可回滚 |

## 3. 实施计划（阶段 4，需确认后执行）

### 3.1 工作包与顺序

**WP1：Kotlin 原生通道（预计 2–3 天）**

- 新增 `android/app/src/main/java/com/webgrab/app/douyin/`：
  - `DouyinLink.kt`：从分享文案提取 URL/aweme_id，支持 `v.douyin.com`、`/video/`、`/note/`、`/slides/`、纯 ID；短链 `GET` 读 `Location`，最多 3 跳，校验域名。
  - `DouyinHttpClient.kt`：单例 client + `JavaNetCookieJar`；iPhone UA、Referer、超时；`fetchSharePage(id, kind)` 两次请求。
  - `RouterDataParser.kt`：括号配对截取 `window._ROUTER_DATA`，`\u002F` 解码，递归找 `play_addr/playwm/images/music`。
  - `DouyinNativeResolver.kt`：编排并输出统一 JSON（见架构文档 §3）。
- 单元测试（JVM）：用保存的 HTML/JSON 片段测解析、短链、错误码；不打网络。

**WP2：Kotlin WebView 兜底（预计 4–6 天）**

- `ParseActivity.kt`：透明、`configChanges`、只承载 WebView。
- `DouyinWebViewEngine.kt`：WebView 设置、UA、注入、JS Bridge、页面状态探测、验证/登录识别、超时（45s/120s）、无响应重建。
- `assets/parser/hook.js`：重写 fetch/XHR，只捕获 `/aweme/v1/web/aweme/detail/`，压缩字段后回传。
- `assets/parser/page_model.js`：扫描页面对象找 aweme_id 对应媒体。
- `DouyinDetailNormalizer.kt`：详情/页面模型 → 统一 items。
- `DouyinResolver.kt`：门面，保持 `resolve(pageUrl, timeoutMs)` 静态签名；内部 native 优先、失败起 WebView；结果缓存 10 分钟。
- 单元测试：normalizer 的 snake_case/camelCase/图集/LivePhoto/缺字段；错误分类；不依赖网络。

**WP3：Python 适配（预计 1–2 天）**

- `engines.py`：桥返回 items 列表；新增 `DouyinError(code, message)`；缓存 key 改 aweme_id；第三方链仅在 `douyin_mode=third_party` 执行。
- `extract.py`：抖音优先桥；图集去重；`/slides/` 与纯 ID；平台引擎异常不再吞掉。
- `server.py`：`/api/scan*` 透传 `error_code`；heartbeat；`/api/config` 允许空 `douyin_apis` 与 `douyin_mode`。
- `tests/`：桥 JSON → item 映射、图集、错误透传、缓存、`/api/dl` 重试。

**WP4：前端适配（预计 1 天）**

- `app.js`：`SSE_IDLE=45000` + ping；错误卡按 code 显示动作；图集渲染复用现有 grid；帮助弹层文案改为“本地/第三方”。
- `tools/ui_test.py`：新增“图集 N 项”“验证提示”“登录提示”“心跳不误判超时”断言。

**WP5：构建与真机（预计 2 天，依赖用户 USB）**

- `copy_python.ps1` 同步；`build_apk.ps1` 构建 release；安装到 `22554a8a`（或用户当前设备）。
- 真机验证：视频、图集、LivePhoto、转音频、分享入口、后台下载、通知、验证场景。
- 更新 `dist`、`SHA256SUMS.txt`、`使用说明.md`、`docs/DOUYIN.md`。

### 3.2 文件影响面

| 文件/目录 | 变更 |
|---|---|
| `android/.../douyin/*.kt` | 新增 6–8 个文件 |
| `android/app/src/main/assets/parser/*.js` | 新增 2 个文件 |
| `android/app/src/main/AndroidManifest.xml` | 注册 `ParseActivity`（透明、exported=false） |
| `core/webgrab/engines.py` | 桥多 item、错误码、模式开关 |
| `core/webgrab/extract.py` | 抖音分支、去重、异常 |
| `core/webgrab/server.py` | 心跳、错误透传、config |
| `core/webgrab/static/app.js` | SSE/错误/图集 |
| `tools/ui_test.py`、`tests/` | 新增断言与单测 |
| 文档 | DOUYIN/使用说明/README 更新 |

不改：下载器、转换器、预览层核心逻辑、其他平台解析路径。

### 3.3 依赖选择

- 原生通道优先用 Android 内置 `HttpURLConnection` + `CookieManager`，避免新增 OkHttp；若需要连接复用/拦截，再引入 OkHttp（已有依赖可复用，需评估 APK 体积）。
- WebView 注入优先 `androidx.webkit` 的 `addDocumentStartJavaScript`；若版本不满足，退回 `onPageStarted` 注入（已验证可行）。
- 不新增任何 native 库；ffmpeg-kit 不变。

## 4. 测试计划（阶段 4 必须覆盖）

### 4.1 十类抖音用例

| # | 用例 | 预期 |
|---|---|---|
| 1 | 普通视频链接 | 成功，视频 item，可下载 |
| 2 | `v.douyin.com` 短链 | 成功；过期短链 → `SHORT_LINK_UNRESOLVED` |
| 3 | 完整分享文案 | 提取链接成功 |
| 4 | 图集/`note` 链接 | 多图片 item；未验证前标注“待真机” |
| 5 | 正常公开页面 | 成功 |
| 6 | 页面不存在/链接失效 | `NO_MEDIA`/`PAGE_LOAD_FAILED`，提示具体 |
| 7 | 网络断开 | `NETWORK`，不误报解析失败 |
| 8 | 页面加载超时 | `DETAIL_TIMEOUT`/`PAGE_LOAD_FAILED` |
| 9 | 登录/验证页面 | `NEEDS_LOGIN`/`NEEDS_VERIFICATION`，提供“打开页面”，不自动绕过 |
| 10 | 媒体地址失效 | `/api/dl` 重解析一次，仍失败提示“直链已过期” |

### 4.2 回归

- 其他平台图片/视频扫描；预览（图片/视频）；单选/全选/批量下载；单文件下载；MP3/M4A/WAV；上传转换；链接转换；后台下载与通知；分享入口；下载目录；360/393/430 布局；`ui_test.py` 原 50 项。
- Android 8/10/13/16 权限差异（至少真机 Android 16 + 一个低版本模拟器/真机，若可用）。

### 4.3 隐私检查

- 抓包/日志确认：本地模式下没有请求发往第三方解析域名；日志无 Cookie、无签名 query；APK 内无 GPL 代码。

## 5. 验收标准

1. 真机公开视频：原生通道 ≤10s 出结果；WebView 兜底 ≤30s。
2. 真机公开图集：≥2 张图片正确显示并可批量下载（需用户提供样本）。
3. 失效链接/断网/超时/验证/登录五类错误均有不同中文提示与可行动作。
4. 验证场景：提示后打开页面，用户完成后能自动继续并成功。
5. `pytest`、`smoke_test.py`、`ui_test.py` 全绿；原功能无回归。
6. `apksigner verify`、`zipalign -P16` 通过；`dist` 更新 hash。
7. 本地模式下抓包无第三方解析请求。

## 6. 风险、回滚与待确认

### 6.1 主要风险

- 抖音改版导致原生/钩子同时失效：只能回退第三方模式或等待适配；不承诺长期可用。
- 图集未验证：阶段 4 若失败，先交付“视频可用”，图集单独排期。
- WebView 内存与验证交互：需要真机调；低端机可能 OOM。
- 新增 Kotlin 代码量（约 1,200–1,800 行）带来维护成本。

### 6.2 回滚

- 基线：`git tag baseline-v1.0.0`（提交 `17e0067`）。
- 开发分支：`feature/douyin-local`；每个 WP 单独提交。
- 配置回退：`douyin_mode=legacy` 走旧链路；APK 可回装旧版 `dist/网页抓取器-1.0.0-arm64.apk`。

### 6.3 需要用户确认/提供

1. 一个**有效的抖音图集分享链接**（用于验证图集，当前没有样本）。
2. 是否允许保留“第三方模式”作为默认关闭的应急开关；若不允许，阶段 4 删除该入口与调用。
3. 真机 USB 可用时间（安装与验证）。
4. 是否接受“无水印”仅作为透传事实、不做承诺。
