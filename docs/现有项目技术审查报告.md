# 现有项目技术审查报告

- 审查对象：`webgrab`（「网页抓取器」v1.0.0 Android APK，包名 `com.webgrab.app`）
- 审查日期：2026-11-14
- 审查方式：只读静态审查 + 仓库内自动化测试 + 既有真机/桌面验证记录复核；**本阶段未改动任何代码**
- 代码基线：工作副本无 git 仓库（`git status` 返回 `fatal: not a git repository`），因此没有可引用的 commit。本报告中的行号对应当前工作副本。
- 审查限制：
  1. 手机当前未连接（`adb devices` 为空），无法对 Android 运行时做新增验证；
  2. 抖音页面存在风控与地域差异，本轮不重复做大规模线上探测；
  3. 未上架、未混淆，release APK 为本地自签名。

## 0. 结论摘要

1. **现有抖音解析不是“单点失败”，而是四层链路的组合问题**：Android 隐藏 WebView（唯一在 Android 上真正可用的层）与前端 8 秒 SSE 空闲回退互相踩踏；图集在桥里没有实现；错误在 `scan_page` 里被吞掉；第三方接口开关名不副实。
2. **最关键的确定性缺陷**：`app.js` 的 SSE 空闲阈值是 **8 秒**，而 Android 桥单次解析预算是 **25 秒**，桥执行期间服务端不发任何 SSE 事件。只要桥阶段超过 8 秒（正常网络下是常态），前端就会判定“连接不稳定”，关闭 SSE、再发一次 `POST /api/scan`，服务端同时跑两份解析（两个隐藏 WebView），既慢又更容易触发风控。
3. **图集/图文作品目前没有可用路径**：Android 桥只返回单个视频 URL（`_bridge_result` 只产出一个 `kind=video` 的 item），直连层依赖已失效的 iesdouyin SSR，第三方接口又不满足“完全本地”的新要求。用户明确要求的“视频和图集”中，图集属于未实现。
4. **“关闭抖音第三方解析”并没有真正关闭**：`tp` 只传到 `extract.filter_candidates()`，`resolve_douyin()` 仍会无条件请求配置里的第三方 API；且配置校验要求至少 1 条，前端传空数组会被拒绝，用户无法清空。
5. **可复用的基础不少**：统一 item 结构、`/api/dl` 的过期重解析、DownloadManager 下载、转换链路、SSE 协议、WebView 壳都可以保留。第二阶段应把“解析”抽成可插拔 resolver，而不是继续在 `engines.py` 里叠 if。

## 2. 运行时架构

### 2.1 启动链

```
MainActivity.onCreate
  └─ startForegroundService(GrabService)
       └─ GrabService.doStart()                        # GrabService.kt:88-140
            ├─ Python.start(AndroidPlatform(this))
            ├─ extractStaticDir()                       # assets/webgrab-static → filesDir/static
            ├─ os.environ: WEBGRAB_HOME=filesDir/webgrab
            │              WEBGRAB_STATIC_DIR=filesDir/static
            ├─ android_entry.start(8765, staticDir)     # 返回实际端口（8765-8799）
            └─ SharedPreferences("webgrab"): state/port/error
  └─ waitForServer() 轮询 prefs（最长 60s）              # MainActivity.kt:235-…
       └─ webView.loadUrl("http://127.0.0.1:<port>/")
```

- WebView 的 UA 追加 `WebGrabAndroid/1.0.0 WebGrabNative/1.0.0`（`MainActivity.kt:51,147`），前端据此区分“普通手机浏览器”和“原生 App”。
- 分享入口：Manifest 的 `ACTION_SEND text/plain` → `onCreate`/`onNewIntent` 取 `EXTRA_TEXT` → 若服务未就绪先存 `pendingShareText`，就绪后 `webView.loadUrl(shareUrl(text))`（`MainActivity.kt:343-359`）。
- 停止：`GrabService.stopServer()` 最终 `Process.killProcess(myPid())`（Python 线程无法 join）。**这会把整个 App 进程（含 UI）一起杀掉**，属于已知折衷。

### 2.2 HTTP 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/` `/demo` `/share` | 首页、示例页、分享落地页 |
| GET | `/api/health` | `{ok,version,ffmpeg,convert,platform,port}` |
| POST/GET | `/api/scan`、`/api/scan_stream` | 扫描；后者为 SSE |
| GET | `/api/dl` | 直链/HLS/yt 下载（流式；Range） |
| GET | `/api/hls`、`/api/yt` | HLS 转封装、yt-dlp 下载并合并 |
| GET | `/api/proxy` | 媒体代理（透传 Range） |
| POST/GET | `/api/convert/upload`、`/api/convert/link`、`/api/convert/file` | 上传转换 / 链接转换 / 取产物 |
| GET/POST | `/api/config` | 读写抖音接口列表 |
| GET | `/manifest.webmanifest`、`/sw.js`、`/static/*` | PWA 与静态资源 |

- 服务端 `ThreadingHTTPServer`（`daemon_threads=True`），每个请求一个线程；只校验 `Host` 为 `127.0.0.1[:port]`，无鉴权。
- 静态文件支持 Range（206 + `Content-Range`）。
- `/api/dl` 的抖音重试：当响应 403/404/HTML 且 `page`/`via=dy` 存在时，调用 `_refresh_douyin_item(page)` → `resolve_douyin(use_cache=False)`，成功后用新直链重试一次；仍失败返回 `{"ok":false,"error":"抖音直链已过期，请重新解析"}`（`server.py:76-90,350-389`）。

### 2.3 下载与转换

- 下载：前端 `<a download href="/api/dl?...">` 或 `dlUrl()` → WebView 触发 `DownloadListener` → `DownloadManager` 落盘 `Download/网页抓取器/`（`MainActivity.kt:193-195,386-408`）。DownloadManager 会带 WebView UA 与 Cookie（对 `127.0.0.1` 的 Cookie 实际无关紧要）。
- 转换：`media.py` 桌面走 `subprocess`，Android 走 Chaquopy Java 桥调 `FFmpegKit.execute`；必须先去掉 argv[0]（FFmpegKit 会自动补 `ffmpeg`/`ffprobe`），用 `ReturnCode.getValue()==0` 判成功。产物 TTL 1 小时。

## 3. 抖音解析的实际执行流程

### 3.1 入口与链接归一

1. 前端把输入原样提交（可能是裸链接、分享文案、纯数字 ID）。
2. `extract.scan_page()` 先调 `engines.douyin_link_from_text()`（`engines.py:405-422`）：
   - 正则 `_DOUYIN_TEXT_RE` 从分享文案里取链接；
   - 否则 `net.first_url()` 取第一个 URL 且必须是抖音域；
   - 否则把 15–25 位纯数字当成作品 ID。
3. `engines.douyin_page_url()`（`engines.py:425-441`）归一成 `https://www.douyin.com/video/<id>`；`v.douyin.com` 短链会手工跟随最多 3 跳 302（`engines.py:379-402`）。
4. `_VIDEO_ID_RE = /(?:share/)?(?:video|note|slides)/(\d{6,})/`（`engines.py:18`）——**note/slides 也会被改写成 `/video/<id>`**，这一步对图集是否成立未验证。

### 3.2 页面抓取与分支

`scan_page()`（`extract.py:470-602`）：

```
先抓页面（普通 UA 失败再桌面 UA）→ extract_media → filter_candidates → build_items
├─ 若页面已有 items：
│   ├─ 平台是 bilibili/weibo/youtube/douyin → 先跑平台引擎
│   │    ├─ douyin → resolve_douyin(raw_input)
│   │    ├─ 其他   → ytdlp_resolve(link)
│   │    ├─ 引擎返回视频 → 视频 + 页面图片合并去重返回
│   │    └─ 引擎抛异常   → except Exception: pass  ← 关键：静默吞掉
│   └─ 直接返回页面 items（engine="direct"）
└─ 页面没有 items：
    ├─ douyin → resolve_douyin(raw_input)，失败抛 ScanError
    ├─ 其他   → ytdlp_resolve(link)，失败按平台抛 ScanError
    └─ 仍无 → "这个页面没有能下载的东西"
```

### 3.3 `resolve_douyin()` 四层链

`engines.py:575-667`，顺序固定：

1. **缓存**：键是用户原始输入（含分享文案），成功 TTL 10 分钟、失败 TTL 2 分钟（`_cache_put`）。
2. **Android 桥**（仅 Android；`page_url` 非空时）：`_android_bridge_resolve(page_url, 25000)`（`engines.py:317-348`）。
3. **直连**：`douyin_direct()`（`engines.py:444-516`）请求 `https://www.iesdouyin.com/share/video/<id>/`，解析 `_ROUTER_DATA`/JSON blob/整页正则。**该 SSR 路径目前已无媒体数据，属于事实上的死路径。**
4. **yt-dlp**：`ytdlp_resolve()`，抖音通常返回“需要登录”。
5. **第三方 API 链**：遍历 `config.douyin_apis`，8 秒超时；默认唯一一条 `https://api.xingzhige.com/API/douyin/?url={url}`（`config.py:16-18`），早已连不上。
6. 全部失败 → 字符串拼接：`抖音解析失败：<桥原因> / 直连无数据 / yt-dlp 无数据 / 第三方接口连不上`。

### 3.4 Android 桥的实现细节

`DouyinResolver.kt`（539 行）：

- 调用约定：`DouyinResolver.resolve(pageUrl, timeoutMs=25000)`，任意线程可调，返回 JSON 字符串，不抛异常。
- 在主线程创建 **1×1 隐藏 WebView**（能拿到 `WebGrabApp.currentActivity` 就挂到 `android.R.id.content`，拿不到就“游离”加载）。
- **第一轮**：桌面 Chrome UA 打开 `https://www.douyin.com/video/<id>`；`shouldInterceptRequest` 拦截 `douyinvod` 等视频请求并返回空响应（阻断真实下载），同时每 700ms `evaluateJavascript` 读 `video.currentSrc`；预算 **8 秒**。
- **第二轮**：第一轮无果 → 移动 UA 打开 `https://m.douyin.com/share/video/<id>`，只读 `video.src`（`playwm`，带水印）；总预算 **25 秒**。
- 返回字段：`{ok, video_url, title, cover, error, referer, watermark}`；Python 侧 `_bridge_result()` 转成单个 `kind=video` item（`via=dy`、`source=douyin`、`page`、`referer`），无图片、无图集。

### 3.5 时序（现状）

```
app.js: 点解析
  ├─ EventSource /api/scan_stream?url=…&tp=0
  │    └─ server: scan_page → 抓页面 → report("engine")
  │         └─ resolve_douyin → DouyinResolver（最长 25s，期间无 SSE 事件）
  └─ 8s 无事件 → fallback: 关闭 SSE，POST /api/scan
       └─ server 再跑一遍 scan_page + 第二个 WebView
```

## 4. 失败环节定位

> 级别：P0 = 直接导致“抖音不可用”；P1 = 明显影响成功率/体验；P2 = 结构性风险。

| ID | 级别 | 现象 | 证据 | 影响 |
|---|---|---|---|---|
| F1 | P0 | 每次解析约 8s 后自动“回退”，服务端并发跑两份解析 | `app.js:16`（`SSE_IDLE=8000`）、`:306`、`:296-302`；桥预算 25s（`engines.py:317`） | 慢一倍、双 WebView、更易触发风控；SSE 形同虚设 |
| F2 | P0 | 图集/图文作品解析不出多图 | `_bridge_result` 只产出一个 video item（`engines.py:351-376`）；桥只读 `<video>` | 不满足“视频和图集”要求 |
| F3 | P1 | 过期短链/无效链接要等 25s，错误笼统 | `douyin_page_url` 跟随 302 到首页后仍返回该 URL（`engines.py:436-441`）；桥报“页面没有返回可用的视频地址…” | 用户无法区分“链接失效”与“网络问题” |
| F4 | P1 | 抖音页只出封面图，却显示解析成功 | `extract.py:556-557` `except Exception: pass`，随后返回页面 items（`engine="direct"`） | 假成功，用户以为抓到图；错误被吞 |
| F5 | P1 | 关闭“抖音第三方解析”后仍请求第三方 API | `tp` 只用于 `filter_candidates`（`extract.py:507`）；`resolve_douyin` 无条件遍历 API（`engines.py:650-663`） | 违背“完全本地”要求；隐私承诺与实际不符 |
| F6 | P1 | 用户无法清空第三方接口 | 前端发送 `{douyin_apis: []}`（`app.js:789`）；`validate_douyin_apis` 要求 1–5 条（`config.py:62-63`） | 开关/设置名不副实 |
| F7 | P1 | 后台/无 Activity 时桥走“游离 WebView” | `attach()` 在无 Activity 时返回 null（`DouyinResolver.kt:373-390`）；`WebGrabApp.currentActivity` 可能为空 | 页面可能不加载/定时器被节流，成功率不可控 |
| F8 | P1 | 需要登录/验证码/风控页时没有专门识别 | 桥只在 `onReceivedHttpError`/`onReceivedError` 报“HTTP 4xx/页面加载失败”；无 DOM 特征判断 | 错误分类达不到用户要求的 7 类 |
| F9 | P1 | 错误全是字符串，前端只能整段展示 | `ScanError(message)`、`EngineError(text)`；无 error code | 无法做“重试/换源/去登录”的分支交互 |
| F10 | P2 | 直连层每次先打 iesdouyin，稳定失败 | `engines.py:444-516`；HANDOFF §9 记录 2026-11 起无数据 | 浪费 1–12s，拉长失败时间 |
| F11 | P2 | 缓存按原始文本做键，直链过期后仍可能命中 | `engines.py:583,622`；成功 TTL 10 分钟 | 下载时才重解析（`/api/dl`），列表预览可能拿到旧直链 |
| F12 | P2 | 停服务靠杀进程 | `GrabService.stopServer()` `Process.killProcess` | UI 一起退出；无优雅关闭 |
| F13 | P2 | 明文 HTTP 全局放开 | `AndroidManifest.xml:15-22` `usesCleartextTraffic=true` | 任意明文请求都被允许，非本地服务也可走明文 |
| F14 | P2 | 源码双份、无版本控制 | `android/app/src/main/python`、`assets/webgrab-static` 由 `copy_python.ps1` 生成；`git status` 失败 | 改 `core/` 忘了同步会打进旧代码；无法回滚 |
| F15 | P2 | 桥一次解析阻塞调用线程 25s | `DouyinResolver.resolveBlocking` 的 `latch.await`（`:302,323`） | 每个扫描占一个服务线程；并发批量扫描会堆积 |

### 4.1 十类要求测试与现状对照

| 要求场景 | 现状 | 结论 |
|---|---|---|
| 普通抖音视频链接 | 桥第一轮设计支持；PC 无头 Edge 验证过页面能出 `currentSrc`；**Android 端未验证** | 设计可行，待真机 |
| 短链接 | `_follow_redirects` 处理正常短链；过期短链会落到首页 | 部分支持，错误不清晰 |
| 完整分享文案 | `douyin_link_from_text` 支持 | 支持 |
| 图片/图集链接 | 桥无图集；直连死；第三方不可用 | **未支持** |
| 正常公开页面 | 页面抽取链路成熟 | 支持 |
| 页面不存在/链接失效 | 归为 HTTP 4xx 或桥超时 | 分类不足 |
| 网络中断 | `ScanError("打开页面失败：网络连不上")` | 有，但桥阶段的断网无独立分类 |
| 页面加载超时 | 桥返回“解析超时（25s）” | 有 |
| 登录/验证页 | 无 DOM 识别，只能等超时 | **未支持** |
| 媒体地址失效 | `/api/dl` 有一次重解析 | 有，但依赖 `page`+`via` |

## 5. 可保留 / 需修改 / 需新增

### 5.1 可以保留

| 模块 | 原因 |
|---|---|
| 统一 item 结构（`id/kind/url/thumb/name/ext/size/w/h/referer/source/via/page/watermark`） | 已被预览、下载、转换、代理共用，扩展字段成本低 |
| `scan_page()` 的页面抽取（`extract_media`/`build_items`/去重） | 对其他平台稳定，是“兜底通道”的基础 |
| `/api/dl` 的 403/404/HTML 重解析 + Range 透传 | 直链过期场景的正确处理，保留并复用 |
| `DownloadManager` 下载、转换链路、SSE 协议 | 与解析解耦，可不动 |
| `DouyinResolver` 的 WebView 骨架 | 双 UA、拦截媒体、轮询、超时、销毁逻辑齐全，可作为“通道 B” |
| `tools/ui_test.py`（50 断言）、`tests/`（26 用例）、`smoke_test.py`（74 项） | 回归基线，需扩充而非重写 |

### 5.2 需要修改

## 6. 新解析器的最佳接入位置

> 以下是第二阶段的设计建议，本阶段不实施。

```
core/webgrab/
├─ models.py          # MediaItem / ParseResult / ParseError（dataclass）
├─ resolvers/
│  ├─ base.py         # class Resolver: can_handle(url) -> bool; resolve(ctx) -> ParseResult
│  ├─ registry.py     # 按优先级注册：douyin_native → douyin_webview → generic_page → ytdlp
│  ├─ douyin.py       # 平台识别、短链、视频/图集归一、缓存、错误码
│  └─ douyin_bridge.py# 仅 Android：调用 DouyinResolver，超时/取消/结果转换
├─ extract.py         # 只保留通用页面抽取，作为 generic_page resolver
├─ engines.py         # 保留 yt-dlp/其他平台，不再承载抖音四层 if
└─ server.py          # scan 入口改为 registry.resolve()，SSE 发阶段事件
```

接入点选择理由：

1. **`scan_page()` 是唯一入口**（`/api/scan`、`/api/scan_stream`、`/share` 都走它），在这里切到 registry 改动面最小。
2. **`_engine_items()` 已经是“引擎结果 → 统一 item”的适配层**（`extract.py:399-467`），新 resolver 直接返回统一模型即可复用。
3. **`/api/dl` 的重解析逻辑只依赖 `page` + `via`**（`server.py:76-90`），新模型保留这两个字段即可继续工作。
4. **`DouyinResolver` 保持 Kotlin 侧不变职责**：只负责“打开页面、等媒体、返回结构化 JSON”，把“选哪个通道、缓存、错误分类”留给 Python，避免业务逻辑散在两门语言里。

建议的双通道职责：

| 通道 | 职责 | 触发条件 | 输出 |
|---|---|---|---|
| A 原生网络 | 短链归一、公开页 SSR/JSON、图集 | 每次优先（带 3–5s 预算） | 视频/图集 item |
| B WebView | 页面渲染后取 `video.currentSrc`/图集 DOM | A 失败或页面需要 JS | 视频/图集 item |
| C 第三方 API | **默认关闭**，仅用户显式开启 | 用户配置且开关打开 | 视频/图集 item |
