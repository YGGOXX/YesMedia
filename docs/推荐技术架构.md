# 推荐技术架构（第二阶段）

日期：2026-11-14  
前置：`docs/现有项目技术审查报告.md`、`docs/抖音解析方案对比.md`  
状态：**设计稿，未写实现代码、未构建 APK**。所有“已验证”仅指本机 PC 级验证，Android 端需阶段 4 真机复测。

---

## 1. 设计目标与边界

目标：

1. 抖音解析在 Android 本机完成，不依赖自建服务器、不依赖第三方在线解析 API。
2. 同时支持公开**视频**与**图集/LivePhoto**，输出与现有媒体网格相同的 item 结构。
3. 不破坏现有网页图片/视频解析、预览、下载、音频转换、分享入口。
4. 失败必须可区分（链接、网络、超时、验证、登录、无媒体、直链过期），不能一律“网络问题”。
5. 保留 Kotlin + Chaquopy + Python 本地服务架构，解析放 Kotlin，编排与下载放 Python。

不做：

- 不绕过登录、验证码、DRM、付费或访问权限；遇到验证/登录只提示用户手动完成。
- 不把第三方 API 作为默认链路；不把 Cookie/链接上传到第三方。
- 不一次性重写现有解析器；旧实现保留在仓库中，可回滚。

---

## 2. 总体结构

```
Android UI (WebView)
  └─ http://127.0.0.1:<port>
       └─ Python core/webgrab/server.py
            └─ engines.resolve_douyin()
                 └─ Kotlin bridge  com.webgrab.app.douyin.DouyinResolver.resolve(pageUrl, timeoutMs)
                      ├─ 通道 A：DouyinNativeResolver   （优先，2–6s）
                      │    ├─ 分享文案/短链 → aweme_id / 规范页
                      │    ├─ OkHttp + 持久 Cookie（ttwid）
                      │    ├─ 两次请求 iesdouyin 分享页
                      │    └─ 解析 _ROUTER_DATA → 统一 JSON
                      └─ 通道 B：DouyinWebViewResolver （兜底，7–45s）
                           ├─ 透明 ParseActivity + 单 WebView
                           ├─ document-start 注入 hook.js
                           ├─ 拦截 /aweme/v1/web/aweme/detail/ 的 JSON
                           ├─ page_model.js 扫描页面对象
                           └─ 验证/登录/超时检测 → 统一 JSON
```

关键点：

- **只有 Kotlin 直接接触抖音页面与 Cookie**；Python 不保存抖音 Cookie。
- Python 只接收统一 JSON，再映射成现有 item；下载仍走本地 `/api/dl`。
- 两条通道返回同一个 schema，Python 不关心是原生还是 WebView。
- 旧的三层链（直连/yt-dlp/第三方 API）保留代码，但默认不执行；通过配置 `douyin_mode` 控制。

`error_code` 取值（与 DouyinKit 的错误分类对齐，但由本项目的 Kotlin 输出）：

| code | 含义 | 前端动作 |
|---|---|---|
| `NO_LINK` | 文案里没有抖音链接 | 提示重新粘贴 |
| `UNSUPPORTED_HOST` | 不是抖音域名 | 提示不支持 |
| `SHORT_LINK_FAILED` | 短链请求失败 | 可重试 |
| `SHORT_LINK_TIMEOUT` | 短链超时 | 可重试 |
| `SHORT_LINK_UNRESOLVED` | 短链没跳到作品页（过期/活动页） | 提示重新复制分享链接 |
| `PAGE_LOAD_FAILED` | 页面打不开 | 可重试/打开页面 |
| `DETAIL_TIMEOUT` | 等作品数据超时 | 可重试 |
| `NO_MEDIA` | 页面没有可用媒体 | 提示无内容 |
| `NEEDS_VERIFICATION` | 滑块/验证码 | 弹“打开页面完成验证”，完成后自动重试 |
| `NEEDS_LOGIN` | 登录墙 | 弹“打开页面登录” |
| `NETWORK` | 网络异常 | 检查网络 |
| `WEBVIEW_UNAVAILABLE` | WebView 无响应 | 重建后重试 |

注意：阶段 4 在真机上验证后才允许把 `watermark=false` 作为事实展示；当前实现只透传字段，不在 UI 承诺“无水印”。

## 4. 通道 A：原生 HTTP（优先）

### 4.1 流程

1. `LinkExtractor` 从文本中提取第一个抖音 URL；支持 `v.douyin.com` 短码、`/video/`、`/note/`、`/slides/`、纯 aweme_id。
2. 短链用 `GET`（跟随重定向或读 `Location`），最多 3 跳；校验最终 host 仍是 `douyin.com/iesdouyin.com`。
3. 规范化分享页：`https://www.iesdouyin.com/share/{video|note}/{id}/`。
4. OkHttp 单例 + `JavaNetCookieJar`，UA 用 iPhone Safari，`Referer: https://www.douyin.com/`。
5. **请求两次**：第一次拿 `Set-Cookie: ttwid`，第二次带 cookie 解析。若第二次仍无 `play_addr`，重试最多 3 次（间隔 800ms）。
6. 解析 `window._ROUTER_DATA`：按花括号深度截取 JSON（避免正则截断）；兼容 `\u002F` 转义；递归找 `play_addr/playAddr`、`playwm`、`images[].url_list`、`music.play_url`。
7. 视频地址优先取 `play`（去 `wm`）地址；失败回退 `playwm`；两者都在本机验证过 206 `video/mp4`（PC）。
8. 图集按 `images[]` 顺序输出；单图且带 `video` 字段时按 LivePhoto 输出静态图 + 动图两个 item。

### 4.2 已验证与未验证

已验证（PC，2026-11-14）：

- 两次请求：第 1 次 32,334B 无 `play_addr`；第 2 次 37,930B 有 `play_addr`。
- `playwm` 与 `play` 地址均 206 `video/mp4`，总长 420,828,761B，Range 正常。

未验证：

- Android 网络/UA 下是否同样返回（理论上一致，仍须真机复测）。
- 公开图集的分享页是否稳定返回 `images`（缺少有效图集样本）。
- `play` 是否真的无水印（只验证了可下载）。

### 4.3 失败处理

- 3 次仍无媒体 → `NO_MEDIA`，交给通道 B，不直接报错。
- 第 1 次请求 4xx/5xx → `PAGE_LOAD_FAILED`，仍尝试通道 B。
- 短链落到首页（过期链接典型表现）→ `SHORT_LINK_UNRESOLVED`，不盲目请求首页。

## 5. 通道 B：WebView 钩子（兜底）

### 5.1 组件

- `ParseActivity`：透明、无动画、`configChanges="orientation|screenSize|keyboardHidden"`，只负责承载 WebView；由 `DouyinWebViewResolver` 启动，结果通过 `CompletableDeferred` 返回。
- `DouyinWebViewEngine`：单 WebView，桌面 Chrome UA（与已验证的 `video.currentSrc` 路径一致），JS/DOM storage 开，文件访问关，混合内容 `NEVER_ALLOW`，仅允许抖音域名主框架导航，验证 iframe 允许 https。
- `hook.js`：文档开始注入（`WebViewCompat.addDocumentStartJavaScript`，androidx.webkit ≥1.9；不可用时 `onPageStarted` 注入）。重写 `fetch` 与 `XMLHttpRequest`，只处理 `/aweme/v1/web/aweme/detail/`，把 `aweme_detail` 压缩后回传。
- `page_model.js`：详情钩子超时后，扫描 `window.__pace_f / _ROUTER_DATA / __INITIAL_STATE__ / SSR_RENDER_DATA` 与页面对象树，按 aweme_id 找最佳候选。
- `DouyinDetailNormalizer`：只移植/实现必要字段（aweme_id、desc、author、video.play_addr/bit_rate、images、music、duration），不引入 Room/Compose 依赖。

### 5.2 流程与超时

1. 页面开始加载，注入钩子；每 6s 请求一次页面模型；第 7s 起开始探测页面状态。
2. 捕获到详情 JSON 即成功；22s 仍无详情但有页面模型 → 用页面模型降级；45s 仍无 → `DETAIL_TIMEOUT`。
3. 页面文本/URL 命中验证码关键词 → `NEEDS_VERIFICATION`，超时延长到 120s；用户完成验证后自动继续。
4. 命中登录关键词/登录 URL → `NEEDS_LOGIN`，不自动展开登录页，提示用户点“打开页面”。
5. WebView 连续 2 次探测无响应 → `WEBVIEW_UNAVAILABLE`，销毁重建一次后重试。

### 5.3 与当前实现的差异

当前 `DouyinResolver.kt`（539 行）只做“两轮 UA 加载 + 读 `video.currentSrc`”，问题：

- 只能拿视频，拿不到图集；
- 依赖 `WebGrabApp.currentActivity`，Activity 重建/退出会中断；
- 没有验证/登录识别，失败只有一句中文；
- 25s 超时与前端 SSE 8s 空闲冲突（F1）。

新设计保留 `resolve(pageUrl, timeoutMs)` 静态签名，Python 桥不需要改调用方式；内部替换为“原生优先 + WebView 兜底”，图集返回多 item。

## 6. Python 侧改造

### 6.1 `engines.py`

- `_android_bridge_resolve()`：调用 `DouyinResolver.resolve(pageUrl, timeoutMs)`，解析统一 JSON；把 `items` 全部映射为 item：
  - 视频：`kind=video`、`url=item.url`、`ext=mp4`、`via=dy`、`page`、`referer`、`w/h/size`。
  - 图片：`kind=image`、`url=item.url`、`thumb=item.thumb`、`name` 用序号、`via=dy`、`page`。
- `_bridge_result()` 从“单 video”改为“items 列表”；保留 `source="douyin"`、`via="dy"`、`watermark`。
- `resolve_douyin()`：
  1. 缓存（成功 10 分钟 / 失败 2 分钟，key 用 aweme_id 而不是完整短链）；
  2. Android 桥（native→webview 由 Kotlin 内部完成）；
  3. 桌面/无桥时才走旧的 `douyin_direct`/yt-dlp；
  4. 第三方 API 仅在 `config.douyin_mode == "third_party"` 时执行。
- 失败时抛带 `code` 的异常（新增 `DouyinError(code, message)`），`server.py` 输出 `{"ok":false,"error_code":...,"error":...}`。

### 6.2 `extract.py` / `scan_page`

- 抖音链接且 Android 桥可用 → 优先桥；桥返回图集时不再合并页面里重复的图片（按 URL 去重）。
- 保留 `douyin_link_from_text`，但补充 `/slides/`、纯 ID、`iesdouyin.com/share/note/`。
- `scan_page` 的平台引擎异常不再 `except Exception: pass`（F4）；记录原因，页面无 items 时把引擎错误抛出。

### 6.3 `server.py`

- `/api/scan`、`/api/scan_stream`：SSE 事件增加 heartbeat（每 3s 一行 `event: ping`），空闲阈值前端改 45s（F1）。
- `/api/dl`：抖音 item 带 `page`+`via=dy`；403/404/HTML 时重新解析一次；图集图片不需要重试逻辑，但保留 Range。
- `/api/config`：新增 `douyin_mode`（`local` 默认 / `third_party` 显式开启），`douyin_apis` 允许空列表（修 F6 的校验拒绝空数组问题）。

### 6.4 前端 `app.js`

- `SSE_IDLE = 45000`，并在收到 `ping` 时刷新计时。
- 错误卡按 `error_code` 显示：`NEEDS_VERIFICATION` 显示“打开页面完成验证”；`NEEDS_LOGIN` 显示“打开页面登录”；其余给“重试”。
- 图集渲染沿用现有 grid（`kind=image`）；视频 item 的下载按钮仍走 `dlUrl`。
- 帮助弹层里的“抖音第三方解析”开关改为“抖音解析模式”，默认“本地”；第三方模式需二次确认并说明链接会发给第三方。

## 8. 安全与隐私

- WebView：`setAllowFileAccess(false)`、`setAllowContentAccess(false)`、`MIXED_CONTENT_NEVER_ALLOW`、禁止站外主框架跳转、禁用多窗口、关闭地理位置。
- Cookie 只存在 OkHttp `CookieJar`/WebView `CookieManager`，不写日志、不传给 Python、不进备份。
- 日志只打印 path 与错误码，不打印 query、Cookie、完整 JSON（对齐 douyin-material-saver 的做法）。
- 下载仍由本地 `/api/dl` 代理，带 `Referer: https://www.douyin.com/`，不改直链给系统浏览器。
- 明确不实现：验证码识别/破解、登录态伪造、DRM 解密、付费内容绕过。

## 9. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| 抖音改版，分享页不再含 `play_addr` | 通道 A 失效 | 通道 B 兜底；错误码 `NO_MEDIA` |
| 钩子被 CSP/页面改版影响 | 通道 B 拿不到详情 | 页面模型兜底；保留 `currentSrc` 最后手段 |
| WebView 内存/黑屏 | 解析卡住 | 单实例、45s 超时、连续 2 次无响应重建 |
| 图集未真机验证 | 可能只出视频 | 阶段 4 用真实图集链接验证后再宣称 |
| 第三方 API 误触发 | 隐私投诉 | 默认关闭 + 二次确认 + 文档说明 |
| 改坏现有平台 | 回归失败 | `baseline-v1.0.0` tag；分支开发；逐阶段测试 |

回滚：所有改动在 `feature/douyin-local` 分支；`git checkout baseline-v1.0.0 -- <file>` 可恢复单文件；配置 `douyin_mode=legacy` 可退回旧链路（阶段 4 保留一个版本周期）。
