## 2. 拟采用方案涉及的许可证

### 2.1 直接新增

| 组件 | 版本/来源 | 许可 | 用法 | 义务 |
|---|---|---|---|---|
| 自写 Kotlin `DouyinNativeResolver` | 本项目 | 同项目 | 原生 HTTP 解析 | 无 |
| 自写 Kotlin `DouyinWebViewResolver` | 本项目 | 同项目 | WebView 钩子 | 无 |
| `hook.js` / `page_model.js` | 本项目自写（参考 MIT 思路，不复制） | 同项目 | WebView 注入 | 无 |
| `androidx.webkit`（仅当使用 `addDocumentStartJavaScript`） | 1.12+ | Apache-2.0 | 文档开始注入 | 保留 NOTICE |

说明：当前 APK 已有 `androidx.*`、Kotlin 标准库（Apache-2.0）与 OkHttp 可复用；若为减少体积，原生通道也可用 `HttpURLConnection`（Android 内置，无新增依赖）。阶段 3 设计确认时在“OkHttp vs HttpURLConnection”之间二选一，本文件按两者都不新增 GPL 处理。

| 组件 | 许可 | 现状 | 风险 |

## 4. 研究仓库自身的合规注意事项

- `.research/` 目录只用于阅读，**不进入版本库**（已在 `.git/info/exclude` 忽略），不分发。
- 不把 GPL-3.0 项目的代码粘贴进 `core/`、`android/`、`docs/` 的任何交付文件。
- 若后续确实复用 MIT 片段：
  - 在文件头保留原版权行；
  - 在 `third_party/THIRD-PARTY-NOTICES.md` 增加“QingZai / DouyinKit, MIT, Copyright (c) 2026 …”；
  - 在仓库 `third_party/` 放 MIT 全文。
- 代码审查时用 `grep` 检查是否出现 GPL 项目特有的类名/注释/常量命名，避免“看起来是改写”的争议。

## 5. 依赖与供应链风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 抖音页面/接口改版 | 解析随时可能失效 | 双通道 + 错误码 + 可回滚；不承诺长期可用 |
| `ttwid` 机制变化 | 原生通道失效 | WebView 钩子兜底 |
| WebView 钩子被 CSP 限制 | 注入失败 | 页面模型/`currentSrc` 兜底；失败明确报错 |
| androidx.webkit 版本要求 | `addDocumentStartJavaScript` 需较新版本 | 不可用时退回 `onPageStarted` 注入 |
| 自签证书 | 用户安装需允许未知来源 | 使用说明写明；不提交私钥到公开仓库（当前 `webgrab.jks` 已在仓库，仅个人分发，需在公开前移除并轮换） |
| 日志泄露 | 签名 URL/Cookie 进日志 | 只打 path 与错误码；发布前 `grep` 日志 |
| 第三方 API 残留 | 误把链接发给第三方 | 默认 `local`；显式二次确认；文档标注 |

**签名密钥提醒**：`android/keystore/webgrab.jks` 与 `android/gradle.properties` 中的密码目前被纳入基线提交，便于本机回滚构建；如果仓库将来公开或多人协作，必须先移除密钥、改用环境变量并轮换签名。此事不阻塞本阶段，但必须在公开分发前处理。
